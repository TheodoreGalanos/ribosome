# Current support

Ribosome is an early-stage local library. The R1–R7 implementation is complete and available from source. Its automated checks and live trials answer different questions: whether the library carries out the work correctly, and whether a model produces useful behavior on the supplied tasks.

## Available now

| Area | Current capability |
| --- | --- |
| Attachment | Pi and generic connectors, startup or mid-run observation, feedback, and optional steering. |
| Repair and recovery | Cooperative writes, required checks, recorded action outcomes, and owner settlement for uncertain effects. |
| Runtime | Saved continuations, queued child work, responsive state operations, and shared resource accounting. |
| Memory | Scoped records, source-aware context, withdrawal, and ranked text retrieval. |
| Discovery | Bounded evidence investigation, functional definitions, grounded occurrences, and contrast work. |
| Prepared behavior | Pi execution of selected instructions on recipient inputs, with capabilities and admission checks. |
| Laboratory | Isolated agent cases, five-arm system comparisons, protected judging, and contextual admission. |

## Observed checks

The recorded R7 handoff passed 15 focused mechanical check groups and 22 installed-consumer checks. These covered the packaged TypeScript worker and installed Rust executable, attachment and recovery, prepared invocation, fresh checks, and appropriate abstention. Provider fixtures exercised those mechanisms without paid calls.

The combined recovery check applied a repair, interrupted its bookkeeping, resumed with one recorded application, restored the target through a fresh check, and left unchecked downstream work stale. It also verified that retired memory was excluded from the next provider context.

These are recorded implementation checks. See the [validation report](../../validation.md#r7-integrated-qualification-and-handoff) and [sanitized evidence snapshot](../../qualification/evidence.json) for their source state and results.

The [instruction lifecycle example](../../../examples/learned-behavior/README.md#revise-and-reuse-a-known-instruction) connects revision, evaluation, admission, memory, retrieval and execution in one check. A faulty row-reconciliation rule fails a case, a revised rule passes both cases, and a later agent uses it while preserving independent work. A units counterexample then triggers withdrawal. The check confirms that the instruction and its linked memory leave retrieval and that Rust refuses another production invocation. Provider responses are authored; Pi execution and Rust state changes are real.

The external-trajectory campaign also exposed a contrast access bug: checks on a definition's supporting files blocked its delivery and later cleared the reviewer's context. The corrected path checks source availability while keeping donor files outside the review assignment. A regression now covers reading, retrieval, continued context and withdrawal. The live rerun completed with one context segment and saved a rejected match against the inspected GeoPandas excerpts. The [external-data pilot](../../../examples/offline-lab/expanded-results.md) is closed, with its broader system comparison deferred after a negative function result.

## Recorded R7 live trials

| Trial | Observed result |
| --- | --- |
| Long-task continuation | Restart, source withdrawal, and compaction mechanisms worked; the long live task still failed useful delivery. |
| Discovery | The curator saved definitions and investigations, but grounded occurrence delivery remained incomplete. |
| Prepared transfer | A recipient attempted an agent-authored policy with fresh receipts; the trial exhausted its allowance with an incorrect result. |
| Whole-agent comparison | Of four cases per arm, baseline, retry, and critique each succeeded on three; care and candidate each succeeded on two. The study remained inconclusive. |
| Installed learning example | Discovery saved an inconclusive investigation after seven calls. Extraction and the four planned recipient evaluations remained unexecuted because there was no candidate. |

The whole-agent recheck used 20 planned cases and 36 Pi stages. Seventeen cases completed and three exhausted their local allowance. These were small, authored development cases with one repetition. The result supports further investigation; general learned transfer and a benefit over the controls remain open evaluation questions.

## Use it in an application

Begin with observations on real artifacts and checks that express your task's requirements. Add scoped repair where your application coordinates the relevant writers. Evaluate each prepared behavior in the context where you intend to use it.

The local tool adapter runs trusted host commands in working copies. Use a suitably isolated executor for untrusted code. For interruption, backup, and source cleanup procedures, see [Operations](../reference/operations.md).
