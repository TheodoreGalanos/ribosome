# Sources and verification boundary

This plan was prepared against repository commit `2b87a6a0d60694a82d746f1ce0b34740a8fd4e20`. Source references support observations about the baseline. Proposed schemas, architecture changes, test matrices, and success criteria are design decisions, not assertions that these features are implemented or empirically superior.

The repository was inspected through the GitHub connector. A local clone attempt in this planning session failed because the container could not resolve GitHub; no repository build, test suite, or live model qualification was run in this session. The development plan does not rely on pretending otherwise. Earlier review findings must be captured as real regression tests before implementation claims are made.

## External primary references

- **[E1] SQLite WAL:** [official documentation](https://www.sqlite.org/wal.html). Supports the distinction between read/write concurrency and the remaining single-writer/application-lock constraints. It does not prescribe Ribosome's proposed executor design.
- **[E2] Tokio blocking tasks:** [official `spawn_blocking` documentation](https://docs.rs/tokio/latest/tokio/task/fn.spawn_blocking.html). Explains why cancelling an awaiter does not normally abort an already running blocking task. Implement against the project's pinned Tokio release, not unpinned documentation alone.
- **[E3] Pi agent-core context and execution extension points:** [upstream README](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md). Reference for context transformation, provider-message conversion, tool execution, and agent lifecycle integration. Keep the project's pinned Pi combination and prove behavior in adapter tests; upstream main is not the implementation's version pin.
